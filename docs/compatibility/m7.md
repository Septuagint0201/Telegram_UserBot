# M7 Compatibility Set

本文固定 M7 Proactive Pipeline 的实现、测试和安全边界。M7 只允许 synthetic canonical event、fake provider/Telegram、content-free evidence 和 disposable PostgreSQL/Redis；真实私聊、真实 Telegram Session、provider credential、真实 AUTO、真实备份恢复和生产部署继续为 `NOT RUN`。

## 固定组件与策略

| 组件 | 固定版本或默认值 | M7 用途 |
|---|---|---|
| CPython | 3.14.7 | 本地与 Linux CI 执行环境 |
| PostgreSQL / pgvector | 17.10 / 0.8.6 | proactive policy、occurrence、candidate、decision、budget 与 job truth |
| Redis | 8.2.8 | 仅 dispatch/wakeup/cache；丢失后由 PostgreSQL 重建 |
| Scheduler | durable due job + 15 分钟 compensation scan | 恢复丢失唤醒，不为每个联系人盲目调用模型 |
| Quiet hours | 联系人当地 `22:00–08:00` | 初步筛选与最终门禁均重新计算 |
| Absolute no-send | 当地 `00:00–07:00` | 不可由配置或模型放宽 |
| Activity suppression | 最近 meaningful activity 30 分钟 | 抑制主动候选和最终发送 |
| Account budget | 每个 account 当地日最多 10 次 | 计入实际或 `send_unknown` 的主动副作用 |
| Contact budget | close 2、friend/acquaintance 1 次/当地日 | 可由版本化 contact policy 收紧 |
| Bypass | 每个联系人当地日最多 1 次 | 仅明确 `promise_due/event_upcoming`、importance >= 0.90 且窗口即将失效 |

当前 Alembic head 为 `0014_m7_budget_integrity`；M7 proactive 表仍由 `0008_m7_proactive_pipeline` 引入，`0009` 至 `0011` 收紧 M5-M7 durable row、context embedding space 与 erasure target 的跨账户引用，`0012` 为 M6/M7 worker 增加有界退避并为 proactive due job 增加持久化 fencing token，`0013` 绑定 M5 preview 状态身份、M6 review conversation/version 以及 M7 candidate 唯一 decision 和保守 budget reaper 契约，`0014` 为候选、decision、reservation 和预算 bucket 补齐时区、scope、授权代际、持久化绑定与 CAS 结算约束。M7 新增 16 张 proactive 表，并由 `m7_roles.sql` 追加 worker、control、maintenance 和 backup 权限。迁移链必须覆盖 empty→head、head→base→head、previous supported→head、latest partial downgrade→head 和 interrupted resume；角色脚本按 M1 至 M7 顺序执行。

## Candidate 与模型 contract

规则层只允许 `promise_due`、`event_upcoming`、`event_followup`、`relationship_reconnect` 和 `explicit_followup`。每个 occurrence 必须绑定 current typed evidence、source hash、policy version、timezone snapshot、bounded UTC window 和稳定 occurrence key。相同联系人和相交评估窗口内的 occurrence 聚合为一个 candidate envelope；没有 eligible candidate 时不得调用 Proactive Agent。

Proactive Agent 只能返回严格结构化的 `send_now`、`defer_once` 或 `none`。`selected_occurrence_ids` 必须属于当前 candidate，`topic` 是单行短主题，reason code 来自 allowlist；`defer_once` 必须仍在原窗口且最多一次，`none` 是当前窗口终态。未知字段、缺失字段、越权 occurrence、无效时间、NaN/越界 priority 和 JSON 解析错误全部 fail closed。

Main AI 仅在 preliminary gate、预算 reservation 和 text-only proactive context 成功后调用。上下文只包含 candidate topic、typed reasons/evidence 摘要、timezone/local time、relationship、bounded active memory 与 freshness，不包含图片、音频、视频、未确认 candidate、任意联系人列表或模型自由检索结果。Main AI 输出不是发送许可。

## 时间、预算与最终门禁

IANA timezone 使用 `tzdata==2026.3`。DST gap 向安全方向移动，fold 的 quiet-start 取较早 instant、quiet-end 取较晚 instant；候选窗口持久化 UTC 边界，不因 tzdata 更新静默改写。跨午夜 quiet interval 使用真实当地日期计算，窗口结束和 absolute no-send 优先级高于 bypass。

Budget reservation 同时占用 account、contact 和可选 bypass bucket，使用稳定 reservation key、租约和原子容量检查。reservation 在最终生成前持有；HUMAN、PAUSED、maintenance、BLOCKED、activity、policy、mode、evidence、timezone、window 或版本快照变化时释放。Telegram 结果为 success 或 `send_unknown` 时都计入保守预算；未知结果不得自动盲目重发，reconciliation 只允许补全 terminal state。

AUTO 必须在 `app` 的 conversation lock 内通过第二次 final gate 后，才原子创建 outbound delivery group/intents。COPILOT 只创建待管理员批准的 proactive draft；HUMAN、temporary HUMAN、PAUSED、maintenance 和 BLOCKED 不运行主动模型，也不补发错过窗口的 backlog。proactive output 只能证明系统发送过该内容，不能反向证明联系人事实或真人写作风格。

## Job、幂等与权限

Due job 的 key 从 policy、typed source、window 和 generation 派生；重复 tick、重复 enqueue、lease 到期和 worker 崩溃都通过 durable state、递增 fencing token 和 compensation scan 重放。显式失败或 lease 到期均使用有界退避，最多 5 次 execution attempt 后进入 dead letter；同一幂等键的并发 enqueue/reservation 先在数据库事务内串行化，再校验 durable identity。扫描只物化当前仍在窗口内的 occurrence；服务恢复不补发已经结束的窗口。candidate membership、decision、reservation、draft 和 state transition 均保留版本、hash、attempt 和 terminal outcome，普通日志不复制正文。

`worker_runtime` 执行 occurrence/candidate/decision/job/reservation truth；`control_runtime` 只能读取脱敏状态并创建版本化 policy/contact settings command，不能直接更新 candidate、decision 或 budget truth；`telegram_userbot_backup` 只读；maintenance 才拥有显式修复权限。M7 不新增 public route，不允许 Control Bot 读取图片或 API key。
