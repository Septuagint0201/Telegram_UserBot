# M4 Compatibility Set

本文固定M4 Conversation Orchestrator与Main AI的实现、测试和安全边界。M4只允许synthetic fixture、deterministic model/Telegram fake和disposable PostgreSQL/Redis；真实Telegram Session、Bot polling、provider credential和真实AUTO发送均为`NOT RUN`。

## 固定组件

| 组件 | 固定版本或契约 | M4用途 |
|---|---|---|
| CPython | 3.14.7 | 本地与GitLab执行环境 |
| PostgreSQL / pgvector | 17.10 / 0.8.6 | turn、run、grace、draft、control command和intent durable truth |
| Redis | 8.2.8 | 沿用M1通知兼容面；M4正确性不依赖缓存 |
| Model port | `canonical-model-port-v1` | 只向注入fake发送run ID、logical role和input fingerprint |
| Telegram port | M3 stable random ID contract | 只使用注入fake执行read、typing和text send |

Alembic head为`0004_m4_conversation_orchestrator`。迁移链验证empty→head、head→base→head、`0001`→head、`0002`→head和`0003`→head，并执行`m1_roles.sql`至`m4_roles.sql`。M4新增11张表，总表数为50；M3暂缓的turn/model-run宽外键在本迁移关闭。

## Mode与turn

resolver的固定优先级为maintenance、global pause、contact pause、temporary HUMAN、conversation override/account default；operational BLOCKED与base mode分开保存。account control、conversation mode、content revision和turn generation均是单调版本，所有会产生模型调用或Telegram副作用的记录保存适用snapshot。

AUTO eligible incoming使用sliding 3秒debounce与10秒hard cap。turn membership逐条绑定message revision和source event；同一conversation至多一个collecting turn，以及一个ready/generating/output-ready turn。HUMAN、COPILOT incoming、PAUSED和BLOCKED不自动创建响应turn。

## Generation与三秒规则

Main AI run绑定active profile/config/credential version、input fingerprint、prompt/capability hash、attempt、usage和结果hash。provider timeout与incoming race的3秒deadline是两个独立概念。

只有run开始后的新eligible incoming可以获得grace：完整模型结果必须在`t0 + 3s`前完成，且authorization逐项保存当时允许忽略的event ID。Telegram RPC前再次比较实际delta；后续edit、delete、human outgoing、mode/control变化或新增事件不能借用旧authorization。超过deadline的run进入superseded，外部model task被best-effort cancel，晚结果只读取terminal状态而不创建第二条发送路径；pending incoming形成replacement turn。

## 发送、feedback与恢复

输出先规范化和确定性分片，再在同一事务创建delivery group与ordered intents；每段保留stable `telegram_random_id`。首个和每个后续RPC前重新检查mode、operational state、account/mode/content snapshot、精确grace、active generation、lease和group状态。read acknowledgement与typing只在AUTO generation启动；4秒heartbeat续租generation并刷新typing，终止、取消、失败和正常完成均best-effort停止typing。COPILOT/HUMAN/PAUSED不自动read或typing。

confirmed human outgoing、edit/delete、pause、maintenance和control version变化会取消仍未产生Telegram副作用的turn/run/group/intent/draft。已开始或unknown的RPC继续按M3 random-ID reconciliation处理，不盲目重发。全部outgoing chunks核对后，turn和COPILOT draft才进入terminal sent/completed，coverage前进并创建幂等Memory refresh job。恢复AUTO只推进resume floor，不自动补历史；`/reply_pending`是显式且仍受完整门禁约束的例外。

## COPILOT与Control Bot

响应式COPILOT只由`/draft <opaque-target>`触发。draft、immutable revision、30分钟expiry、Send/Edit/Ignore action token和approval均持久化；token绑定allowlisted admin、Bot chat、purpose、draft revision和deadline，并且只能使用一次。Edit创建新revision；Send仍创建`copilot_approved` durable intents并重跑final gate。

Control Bot命令边界支持account/scoped `/ai`、`/human`、`/copilot`、`/mode_inherit`、`/pause`、`/resume`、`/draft`、`/reply_pending`、`/cancel`、`/takeover_end`和metadata-only `/status`。contact参数只接受短期`ct_...` opaque token，不以display name作为身份键。本阶段提供framework-neutral controller和durable repository boundary；Bot polling、contact picker token发行和process wiring属于后续runtime/operations集成。

## 已验证与未验证边界

Windows本机执行Ruff、strict mypy、unit/property/contract测试、build和artifact/secret扫描；由于本机无Docker，PostgreSQL/Redis integration明确为`NOT RUN`。GitLab使用digest-pinned disposable PostgreSQL/pgvector与Redis运行migration、role、wide FK、AUTO、grace、late-result、COPILOT和reconciliation测试，并生成content-free race与acceptance manifest。

在M4证据pipeline通过前，本文件描述的是实现候选而非关闭证据。即使M4关闭，默认CLI仍不会构造Telethon client、读取Session、启动Control Bot/Web App、解密provider key或运行AUTO scheduler；真实Telegram/provider、Ubuntu production、backup/restore、production load和24小时soak继续为`NOT RUN`。真实AUTO只能在M9经单独授权的隔离测试peer验证。
