# M1 Compatibility Set

本文固定 M1 PostgreSQL、pgvector、Redis、Python client 与 disposable integration test
组合。它是 V1 durable-state baseline，不表示 Ubuntu 生产部署已经验证。

## 1. 固定版本

| 组件 | 固定版本 | 固定镜像或包 | 选择说明 |
|---|---:|---|---|
| PostgreSQL | 17.10 | `pgvector/pgvector:0.8.6-pg17-bookworm` | 采用已有一个完整主版本运行经验的 PostgreSQL 17，而不直接采用刚发布的最新 major |
| pgvector | 0.8.6 | 与 PostgreSQL 镜像共同固定 | M1 只建立 extension 和兼容性门禁，不创建业务 embedding 表 |
| Redis server | 8.2.8 | `redis:8.2.8-bookworm` | 仅作 arq wake-up、短租约与可重建加速层 |
| SQLAlchemy | 2.0.51 | PyPI exact pin + hash lock | Async PostgreSQL Core mapping 和显式 UoW |
| Alembic | 1.19.1 | PyPI exact pin + hash lock | one-shot migration；应用进程不调用 `create_all()` |
| psycopg | 3.3.4 | `psycopg[binary]` exact pin + hash lock | Windows 与 Linux CPython 3.14 均有 wheel |
| arq | 0.28.0 | PyPI exact pin + hash lock | durable job 只发送 content-free wake-up |
| redis-py | 5.3.1 | PyPI exact pin + hash lock | `arq 0.28.0` 要求 `redis>=4.2,<6`，因此不采用 redis-py 7/8 |
| Testcontainers | 4.15.0 | dev-only exact pin + hash lock | 仅启用 `postgres` extra；Redis fallback 使用 generic `DockerContainer`，避免其 Redis extra 与 arq 的 client version 冲突 |

`docker` Python package 只在 Windows 依赖 `pywin32`；`dev.lock` 必须保留
`sys_platform == "win32"` marker。仓库测试会拒绝把该依赖无条件带入 Linux CI。

生产和 GitLab Linux 使用 multi-architecture manifest digest：

```text
pgvector/pgvector:0.8.6-pg17-bookworm
  @sha256:7ae6051efd0e60444282c27c7e141af07f322ce033300e727a49c3dd11075e38

redis:8.2.8-bookworm
  @sha256:2f7462b9e93e0a7ae2edf3a0a0babc8a4d29f8bfc50849b906b7caaef925edc1
```

当前 GitLab runner 的 `linux/amd64` 子 manifest 分别是：

```text
pgvector: sha256:f193b9c848deb27b0e892f85ed07b53fd83ccb1feb634ba415b1cdc44411bedc
redis:    sha256:d9f0312a780ed4ad4c22c05790c20b3902498b563ba01f3f1134678b9bd2f311
```

CI 与未来 Compose 固定 multi-architecture digest，让平台选择正确子 manifest；验收 manifest
同时记录实际 server version，防止 tag、manifest 与运行内容不一致。

## 2. 数据与调度边界

- PostgreSQL 是 account、conversation、message revision、mode/control、job、outbox、audit
  与 erasure 的唯一 durable fact source。
- 默认 transaction isolation 是 `READ COMMITTED`；需要串行化的 scope 使用 transaction-scoped
  advisory lock、row lock、version CAS、lease owner 与 fencing token。
- Redis payload 只允许 stable job ID、dispatch generation 和可验证的 correlation metadata；禁止
  message body、Prompt、API key、Session、Telegram access hash 和任意 provider response。
- Redis 清空、通知丢失或重复投递不能改变 canonical state。恢复扫描递增
  `dispatch_generation` 并通过 transactional outbox 重建 content-free wake-up。
- schema migration 由单独 migrator 执行；app、control 和 worker 发现 revision 不等于精确 head
  时 readiness fail closed。

## 3. Migration compatibility window

M1 是第一个数据库 revision：`0001_m1_durable_state`。因此：

- empty/base → head 和 head → base → head 必须在 disposable PostgreSQL 实际通过；
- “previous supported revision → head” 对首个 baseline 为 `NOT_APPLICABLE_BASELINE`，不能伪造为
  已存在的升级证据；
- 从 M2 开始，每个 release 必须验证前一个受支持 revision → head；
- data backfill 使用 `migration_progress` 保存 step、watermark 和 version，测试事务中断后按 CAS
  继续；
- destructive migration 不承诺伪 downgrade，必须以 expand/contract、备份/PITR、最新 erasure
  overlay 和维护者决策处理。

## 4. 验证平台边界

| 平台 | 本阶段证据 |
|---|---|
| Windows 11 / CPython 3.14 | exact hash lock 安装、import、`pip check`、unit/contract/property/static/build gate；本机无 Docker，所以真实 PostgreSQL/Redis 为 `NOT RUN` |
| GitLab Linux / CPython 3.14 | digest-pinned PostgreSQL/pgvector 与 Redis service、Alembic round trip、约束/角色、repository、CAS/lease/fencing、Redis loss/rebuild、redaction、EXPLAIN 和 migration manifest |
| Ubuntu production | `NOT RUN`；Compose、真实 volume、backup/restore、资源限制、24 小时 soak 与 erasure restore drill 在 M8/M9 验证 |

integration test 只使用 synthetic ID 和 synthetic content，不连接 Telegram、模型 provider，也不读取
真实 credential。SQLite、mock 或仅编译 SQL 不能替代 PostgreSQL/Redis 的相应 PASS。

## 5. Upgrade cadence

每月检查一次 PostgreSQL minor、pgvector、Redis patch 和 Python package security/bugfix release。
升级必须重新生成 hash lock、重新解析 multi-architecture digest，并通过完整 M1 integration gate；
PostgreSQL major、Redis major、SQLAlchemy major 或 arq/redis-py compatibility 范围变化必须新增 ADR
或明确的架构变更记录，不能静默漂移。

版本事实来源为官方 [PostgreSQL image](https://hub.docker.com/_/postgres)、
[pgvector image](https://hub.docker.com/r/pgvector/pgvector)、
[Redis image](https://hub.docker.com/_/redis) 与各包的
[Python Package Index](https://pypi.org/)。digest 由 registry manifest/config API 复核。
