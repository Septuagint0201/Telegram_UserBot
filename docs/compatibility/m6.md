# M6 Compatibility Set

本文固定M6 Memory、Summary与Embedding Pipeline的实现、测试和安全边界。M6只允许synthetic canonical message、fake Memory/Summary/Embedding provider及disposable PostgreSQL/Redis；真实私聊、真实Telegram Session、provider credential、AUTO发送、真实backup restore和生产部署继续为`NOT RUN`。

## Trigger与job contract

Memory Pipeline不在Main AI同步回复路径中。quiet window、revision count、token estimate、oldest uncovered deadline、补偿扫描及eligible non-AUTO outgoing按OR计算。一个conversation/job kind最多有一个pending generation；相邻或重叠range合并。领取后range immutable，后续event进入下一generation。PostgreSQL partial unique、row lock、lease owner、fencing token和version CAS共同保证重复wakeup不会产生多个事实结果。

Input manifest按generation绑定ordered typed source membership、current revision/hash、config/prompt/policy/schema版本、token/image estimate及manifest hash，不复制消息正文。Provider timeout、malformed JSON、unknown field、duplicate proposal或scope/hash变化均fail closed，且不阻塞canonical ingest或Main AI。

## Proposal与memory contract

Memory Agent输出只接受严格schema。应用验证account/conversation scope、operation target cardinality、semantic key、JSON payload、长度/分数/时态、禁止instruction字段、current non-redacted source revision/hash和span边界。模型输出在校验及原子事务提交前不是active truth。

可信直接用户陈述或观察、无冲突、非visual-only且confidence至少0.85才允许automatic acceptance。0.60至0.85、冲突、推断、歧义或image-only进入candidate；低于0.60或确定性校验错误进入rejected。Candidate和rejected不进入Context或正式embedding。Lifecycle提供create/update/merge/supersede/invalidate及immutable version chain；semantic key冲突与target version CAS阻止静默覆盖。

## Summary、embedding与erasure

Rolling/daily/weekly summary保存explicit ordered source membership、覆盖range、timezone snapshot和contiguous watermark。late edit/delete先隔离dependent current summary及embedding，再异步重建，不能用summary-of-summary隐藏原source。

Embedding只接受active memory version、active summary version和eligible current canonical message chunk。Candidate、rejected、redacted、forgotten、tombstone、image/audio/video及provider raw body不进入向量。新配置先写shadow space，验证count、dimension、source hash和final delta均一致后才原子替换active binding；查询不混用两个space。

Edit/delete/forget/purge先使memory、summary、embedding、context manifest和cache在读路径不可见，再做one-way content/vector清理。Erasure ledger重复应用幂等；restore必须先重放ledger才能开放检索。M6只验证synthetic ledger replay和derived non-resurrection，真实pgBackRest/restic backup与灾难恢复仍属于M8/M9，状态为`NOT RUN`。

## Control与权限

`/memory_status`只显示freshness、job/candidate/active count及embedding state；`/memory`只列出active memory的opaque `mm_` token、type、status和version，不显示正文；`/memory_candidates`只显示opaque `mc_` token、operation/type、confidence band、evidence count和visual-only标记。`/memory_accept`、`/memory_reject`和`/forget`只创建短期、管理员私聊及action绑定的review request，必须通过非文本callback二次确认；确认结果进入durable worker queue，不冒充已经修改derived truth，也不回显memory正文、完整evidence、API key或provider body。

`control_runtime`只能读取derived metadata并写`memory_review_actions`，不能直接写memory/summary/embedding truth。`worker_runtime`可消费review action并在事务内执行proposal/version/watermark/embedding状态更新。Maintenance拥有显式erasure权限；backup只读。
